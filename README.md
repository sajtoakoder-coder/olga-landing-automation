# Ольга Андреева — лендинг + автоматизация

Лендинг (`site/index.html`) + бэкенд: Telegram-бот-админка, заявки, онлайн-оплата
(ЮMoney, на старте — заглушка), автовыдача после оплаты, слоты расписания,
автоотправка ссылок на Телемост. Всё на Vercel serverless (Python).

## Быстрый старт (5 минут)

```bash
git clone <репозиторий> && cd Olga
pip install -r requirements.txt
pytest                       # все тесты должны быть зелёными
```

1. Создайте бота у [@BotFather](https://t.me/BotFather) (`/newbot`) → получите токен.
2. Скопируйте `.env.example` в настройки окружения Vercel (или в `.env` локально)
   и вставьте `TELEGRAM_BOT_TOKEN`.
3. Задеплойте: `vercel deploy --prod` (или push в подключённый к Vercel репозиторий).
4. Пропишите в env `APP_URL=https://ваш-домен.vercel.app` и откройте
   `https://ваш-домен.vercel.app/api/bot/webhook` — это установит вебхук Telegram.
5. Отправьте боту `/start` — он пришлёт ваш `chat_id`. Вставьте его в
   `TELEGRAM_ADMIN_CHAT_ID` (env на Vercel) и передеплойте.
6. Готово: `/start` теперь открывает админ-меню (Товары · Слоты · Статистика · Настройки).

## Хранилище данных

По умолчанию — JSON-файл (`data/store.json` локально, `/tmp` на Vercel).
На Vercel `/tmp` **не переживает cold start**, поэтому для продакшена подключите
бесплатный Vercel KV / Upstash Redis (Storage → Create → KV): переменные
`KV_REST_API_URL` / `KV_REST_API_TOKEN` появятся автоматически, и хранилище
само переключится на Redis. Ничего в коде менять не нужно.

## Режимы (переключаются только через env)

| Переменная | stub (по умолчанию) | live |
|---|---|---|
| `PAYMENT_MODE` | тестовая страница оплаты, деньги не списываются | редирект на ЮMoney quickpay (`YOOMONEY_SHOP_ID` = номер кошелька, `YOOMONEY_SECRET_KEY` = секрет уведомлений, вебхук: `/api/payment/webhook`) |
| `EMAIL_MODE` | письма логируются + уведомление в бот | реальная отправка по SMTP (`SMTP_HOST/PORT/USER/PASS/FROM`) |

## Локальная разработка

```bash
python scripts/dev_server.py 3000
# сайт: http://localhost:3000  · API: http://localhost:3000/api/products
```

## Что где лежит

```
api/       — serverless-функции Vercel (тонкие обёртки над core/)
core/      — конфиг, маршрутизация (app.py), платежи (payments.py), HTTP-слой
bot/       — обработчики бота (aiogram 3), CRUD товаров, слоты, статистика, уведомления
services/  — email (stub/live SMTP), телемост (отложенная отправка ссылок)
storage/   — хранилище: JSON-файл или Vercel KV/Upstash (авто-выбор по env)
site/      — лендинг (index.html), страница успешной оплаты (success.html)
tests/     — pytest: unit + integration + e2e (181 тест)
seed.py    — 4 дефолтных товара (создаются и автоматически при первом запросе)
```

## Как это работает

- **Заявка с сайта** → `POST /api/booking` → хранилище → мгновенное уведомление Ольге в бот.
- **Оплата**: кнопка на лендинге → `POST /api/payment/create` → страница `/pay`
  (email + выбор слота для консультаций) → stub-подтверждение или ЮMoney →
  `POST /api/payment/webhook` (идемпотентный) → уведомление в бот → автовыдача
  (email со ссылкой / ссылка на success-странице / ничего) → редирект на `success.html`.
- **Товары**: лендинг рендерит секцию «Форматы» из `GET /api/products`;
  бот добавляет/правит/скрывает товары — сайт обновляется сам. Если API недоступен,
  показываются статичные карточки (fallback).
- **Слоты**: Ольга добавляет слоты в боте; клиент выбирает слот при оплате;
  забронированный слот исчезает из доступных; за 20 минут до сессии клиенту
  уходит ссылка на Телемост (задаётся у слота, в Настройках бота или `DEFAULT_TELEMOST_URL`).
  Отложенные отправки проверяются при каждом запросе к API и по крону `/api/cron`.
